# Registration player confirmation feedback

The individual registration wizard serves
`public/assets/js/wizard-ex-checkout.js` directly. Its resource counterpart is
`resources/assets/js/wizard-ex-checkout.js`; the public file is not generated by
the current Mix page mapping. Keep changes to this save interaction consistent
in both files, including the generated Save & Confirm button.

A successful player-details response must identify the requested player and
explicitly confirm success before the card is confirmed. Finish the button as
disabled **Saved & Confirmed**, remove its busy state and spinner, and enable
Continue to Cart only when every player card is confirmed. Do not rely on hiding
a button whose HTML still says Saving.

Disable the card fields during its save and ignore duplicate saves. Validation,
session-expiry, malformed responses and bounded request timeouts must clear the
busy state and leave an unconfirmed card recoverable. An ambiguous network result
must tell the user to reload and check saved details before retrying; do not
automatically replay the mutation. A response for an old card cannot confirm its
replacement.

Regression coverage: `tests/Frontend/checkout-player-save.test.cjs` covers state
transitions; `tests/Frontend/checkout-player-save.browser.cjs` renders generated
cards with real jQuery at phone and desktop widths. These fictional fixtures
do not access production player records or establish deployed behavior.
