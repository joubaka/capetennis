# Documentary historical rating recovery

`ratings:recover-identities EVENT MANIFEST --recorded-by=USER` validates a private documentary manifest without writes. `--apply` records its exact match-side attestations atomically. The recorded actor must be an existing super-user. Keep original documents and the operational manifest outside the repository and web root.

The manifest contains `event_id`, an exact integer `fixture_ids` list, `expected_additional_matches`, `reviewed_at`, `documents` (each with `reference` and `sha256`), and `entries`. Each entry contains `event_id`, `fixture_id`, `fixture_player_id`, `side`, `source_team_id`, `suggested_player_id`, `source_fingerprint`, `target_fingerprint`, `cohort`, `evidence`, `reference`, and `reason`. Generate fingerprints with `HistoricalIdentityReviewService` after independently reviewing the original documents; a current profile link is insufficient evidence. Each referenced fixture must pass the canonical history reader. A fresh manifest must add exactly its listed fixtures; an identical retry creates no duplicate evidence.

Recovery is distinct from an original participant snapshot. It changes no score, roster, player link, ownership or publication flag. It covers only listed fixture sides, never subsequent matches for the same imported player. Evidence is append-only. Source or target changes invalidate admission and immediately withhold affected saved snapshots through batched dependency checks. Ordinary rating refresh remains the canonical way to rebuild the derived snapshot; applying evidence does not itself publish or build ratings.

For the reviewed Synergy Cup 2026 recovery, the operational scope is 79 fixtures and 39 supported imported identities. Fixtures 69839 and 69867 and imported identity 1067 remain excluded. This document provides no production authorization. The schema migration is `database/migrations/2026_10_22_030000_create_historical_identity_recoveries.php`; deploying the schema does not apply evidence.
