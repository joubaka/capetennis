# Private player pilot - shared ability v6 and performance v2

## Private name badges

Browser competition/player displays now show a compact blue shared-ability number beside known player names for the `super-user` role only. Explicit Blade components cover profile headings, the player directory, event entries and results, rankings, competition rosters, fixture/order-of-play lineups and HTML/SVG draw identities. Explicit JavaScript markers cover round-robin matrices, group assignments, order/schedule tables, public round-robin pages and Flexible Monrad names. They never change stored/model names, input values, select options or existing name attributes.

Draw, event-category and ranking-category displays select the exact normalized singles cohort. Legacy draws with missing or cross-event category references use their own canonical draw label and actual registration/player IDs; ambiguous labels and missing cohorts display no badge. Generic profile/directory names show the latest eligible cohort. Tooltips identify the cohort, comparison group and provisional singles interpretation; players from different groups cannot be compared. A doubles-specific label is not silently replaced with a singles or different-age headline. Imported names without an established profile ID have no badge.

The lookup shares one compact published-data snapshot per request. Dynamic lookups use a read-only authenticated, `super-user`-protected endpoint (`player-performance/name-ratings`) with at most 100 player IDs, 100 registration IDs and 100 fixture IDs, at most three loaded players per registration (unsupported larger registrations are omitted), and `private, no-store` responses. Fixture-side lookups resolve actual registrations and draw context, rejecting a mismatched draw/category. Guest/ordinary-role HTML has neither badges nor private assets/payloads. All lookup authorization runs before any rating calculation.

Emails, financial documents, downloadable PDFs/draw packs, native selectors and plain-text/export data remain unchanged. Private badges are removed from separate draw print windows and hidden in browser print styling. Public signed name-only profiles still expose only names to ordinary visitors; authenticated Super Admin visitors can see their private badge.

## Shared ability v6 (primary card)

The primary personal/profile card now estimates relative playing ability using a shared comparison network. The previous performance v2 score remains a secondary summary. They are different measures and must not be compared numerically.

Shared ability uses validated published individual singles matches, validated published team singles rubbers, and published individual finishing order. Doubles and team standings remain outside this ability network. Age, gender, ball and Masters context remain separate. Exact age/gender word-order aliases (`Boys U/13` / `u13 Boys`, including singular boy/girl) normalize together; unrelated category modifiers are retained. Events and regions carry no name-based strength multiplier. Historical links arise only from exact shared player IDs in compatible cohorts.

Actual played matches use bounded v6 score-margin targets in the Bradley-Terry model, retaining weight 1 before event budgeting and 180-day decay. A complete published finishing field supplies a separate, explicitly inferred ordinal constraint: its ordered player targets span +1 to -1, centered at zero, relative to the current mean strength of that field. Named policy constants are ordinal weight 0.2 and target span 1.0. The objective is a weighted quadratic field-relative residual plus actual played likelihood and strength-squared regularization (lambda 0.5). This is an uncalibrated heuristic about rank evidence, not a set of synthetic head-to-head matches or established playing-strength measurements. All ranks receive directional evidence; a true midpoint can legitimately remain 50.

Adjacent rank links preserve topology/provenance only and never enter paired-outcome likelihood. This avoids the v3 equal-win/loss chain cancellation and field-size dilution without expanding N² pair comparisons. Unique complete disjoint A/B fields can form one ordered field (maximum 256 players); other fields never receive arbitrary region ordering. If eligible played outcomes already connect every member of a field in the same event/cohort, its ordinal likelihood is omitted to avoid duplicating those results. Incomplete or disconnected played coverage can retain weaker ordinal linkage. Finishing evidence never becomes direct-match confidence.

All sources use a 180-day half-life: actual matches use credible scheduled dates within the original event window, otherwise conservative event-start proxies; finish constraints use event start. Future scheduled matches are excluded from the shared snapshot. Neither ongoing event-end clamping nor score correction timestamps renew old match weight. The secondary performance v2 retains its original dating and eligibility semantics. Coordinate Newton updates maintain field means incrementally, stopping below movement 0.000001 or at 100 passes; nonconverged/nonfinite snapshots are withheld. Display remains 100 × logistic(centered strength), not a percentile, probability or official UTR. Different cohorts/components cannot be compared.

Shared-only legacy status-0 adapters accept already public scores without changing any stored status/type. Individual rows require canonical score validation, credible terminal legacy sets or a recorded valid preset, consecutive unique set numbering, the required number of winning sets, no sets after completion, exact actual-event registration membership and a consistent declared winner if present. Missing-preset draws use their configured set count, defaulting to best-of-three; a lone 6–0 in best-of-three is incomplete. Legacy result_id-only score rows without safely resolved side-oriented numeric scores remain excluded.

Team rubbers require canonical TeamRubberResultService completion, credible terminal sets and exact profile/history or unique event-side roster identity. Legacy missing draw-category references can resolve from source-team actual-event categories. Null-category source teams additionally require exact event-region membership, matching event year, unique side roster membership, and matching canonical age/gender contexts on both sides. Only a complete leading token prefix of the exact proven region display name can be removed from a legacy team name (e.g Overberg from Overberg Primary Schools 2025); unknown prefixes are not discarded, and age/gender/ball modifiers remain. For null legacy rubber types, only authoritative singleton sides and an explicit Singles/reverse Singles draw label can establish an in-memory singles interpretation; canonical best-of-three defaults then apply if set count is absent. Ambiguous, mixed, doubles, foreign-event and incomplete evidence is excluded. Imported identities require a linked-profile attestation captured during first assignment of a newly created, unplayed fixture with no scores. The current profile link, exact source event/team/category/rank and unique roster mirror must still match that attestation. Old null snapshots are never backfilled with a current identity; historical imports without proof remain excluded. Imported link or roster changes invalidate derived snapshot context. No foreign keys or historical records are repaired.

Every rating remains provisional. Finishing-only evidence, inferred links, sparse direct matches and narrow connections show Limited confidence; this is a qualitative evidence label, not an accuracy probability. Only an entirely played-match connected group with sufficient personal matches and no narrow graph links can show Developing. Played-match and inferred-comparison counts remain distinct. Nearby comparator names/indices are restricted to the same group. Multi-event provenance is sampled to five events for five connecting players.

A complete shared snapshot is built once and cached for five minutes in the filesystem (array cache for tests), not as a stored database rating. Each request hashes exact event/result/draw publication flags before using the cache, even if flags changed without updated_at; flags are checked again afterward. Canonical timestamped source changes also alter the fingerprint. Untimestamped direct score/context edits may take up to five minutes to appear, and calculation time is displayed. Fingerprint queries project minimal public-source state, not contact data. The cache and HTTP views remain private to Super Admin.

Inputs stream in bounded batches. Global safety limits are 1,000 events, 256 category definitions per event, 5,000 player identities and 50,000 comparisons/scored match records; exceeding a limit withholds the whole snapshot, rather than displaying a partial estimate. Invalid scores and ambiguous source relationships never become comparison edges. No ranks, results, players, publication flags, registration or financial state is changed.

## Performance v2 (secondary card)

Super Admin's performance pilot links to a searchable directory of every player at backend/player-performance/players. Personal pages and backend profile cards remain GET-only and restricted to super-user. No score, ranking, result, player or publication record is written.

## Historical sources

Personal ratings consider all eligible published history, not just 12 months or 50 events. Target events stream in batches of 25 and fixtures in batches of 50. Scores and source totals aggregate full history; the view retains the latest 50 finish records and 50 match records per discipline, sorted by date, and reports full counts and all-history exclusion counts. The manual comparison retains its explicitly selected date window and 50-field limit.

Finishes follow the public results page's results_published gate. Latest saved corrections count. Saved ranked fields must have at least two distinct consecutive ranks 1..N, unique player identities and matching recorded event-category memberships. Extra unranked entrants do not erase published finishes. Current withdrawal/deletion does not erase recorded historical ranked membership. Unranked membership counts are disclosed; these entrants are not assumed absent. N means saved ranked finishes, not independently verified starters. Missing/duplicate ranked memberships, duplicate players, mixed disciplines, ambiguous field definitions and fields exceeding the 256-entry validation limit are excluded. Team finishing ranks are not individual ranks.

Head-to-head sources require publicly published events and draws. The finishing-table results_published flag is not required for already public draw scores. Individual matches require two distinct registrations with actual-event category membership, verified player counts, unique consecutive set numbers (including legacy zero-based numbering), valid scores and consistent aggregate/declared winners. Canonical ScoreValidationService enforces configured presets. Legacy draws without presets require credible terminal short/full/pro/tiebreak scores. Scored RR status 2 requires RR workflow and enough set wins to establish completion; legacy status 3 requires the recorded winner and enough configured set wins. Canonical completed status 1 remains authoritative for historical shortened matches without presets, provided the recorded sets are credible and consistent. Unplayed byes never count. Ambiguous/partial score evidence is excluded. Stale category-event references resolve read-only only when a unique same-category field in the actual event contains both registrations; no database repair occurs.

Team singles/doubles use publishedTeamTies and canonical TeamRubberResultService completed outcomes. Exact required player-profile identities on both sides, terminal scores and matching event/draw/tie are required. Immutable participant snapshots are checked through TeamParticipantHistoryService.matches against source team, event, category, region, profile and assigned sides. Without snapshots, exact recorded event-side roster membership is required. Legacy fixtures without a tie can resolve a side only through a unique team matching the fixture region, exact event category and every recorded side player; missing or ambiguous mappings remain excluded. Imported no-profile identities are excluded; names never establish identity.

For secondary performance v2, started ongoing events can contribute published results and their evidence date is the as-of date until the event ends. Future events are excluded.

## Scoring and comparison

Version 2 adds match contributions and all-history coverage; values can differ from version 1. Scores remain provisional and uncalibrated, not official UTR, opponent-strength ratings or selection policy.

Explicit A/B division/afdeling phrases and standalone terminal A/B tokens identify divisions. A plain main category counts as A only when uniquely paired with one matching B field in that event, without competing definitions. Unlabelled/unpaired categories use a separate Open cohort. Ambiguous labels are excluded. Age, gender, ball, region, Masters and team contexts remain distinct. Open and A/B cohorts are separate. Singles and doubles stay separate; the headline is the latest eligible singles cohort. No eligible data means Unrated.

Placement points = band minimum + band width * (N-position)/(N-1). A is 50-100, B is 0-50, Open is 0-100. For each event/cohort, placement points form an average finish component. Match win fraction maps into the same tier band as the match component. Both components contribute equally when available; otherwise the single component supplies the event score. Each event has one weight regardless of match count, avoiding doubled event weight from finishes plus matches.

Event scores average with a 180-day half-life, 0.5^(days since event/180), rounding once for display. Older history still contributes with lower weight. Eligible finish/match counts, opponents, outcomes and scores (player first) are shown. Qualification earns no bonus. Doubles describe partnership performance.

Validate familiar players and calibrate assumptions before publication or operational use. Local implementation does not grant publication authority.


## Private evidence confidence (policy v1)

Every Super Admin ability badge displays Low, Medium or High evidence confidence beside the ability number. The internal 0–100 index remains unchanged and is not displayed as accuracy, probability, selection policy or official UTR. Numeric thresholds are Low below 40, Medium below 70, otherwise High; structural restrictions apply before showing High.

Only the player's own eligible individual/team singles evidence in that exact cohort supplies activity, volume and diversity. Each own match contributes a 90-day half-life weight. For each distinct opponent and event, retain the maximum own-match weight. Base points are 50 × min(effective matches / 12, 1) + 25 × min(weighted opponents / 6, 1) + 25 × min(weighted events / 3, 1), multiplied by the latest own direct-match freshness weight. Fewer than 3 effective matches caps at 25; fewer than 5 caps at 45; fewer than 3 weighted opponents or 2 weighted events caps at 65. Inferred or narrow component links cap direct confidence at 75. Own finish evidence provides a separate floor of 15 × its freshness weight, never more than 15. A recent finish does not refresh old direct counts or dates. All eligible published evidence contributes through the separate v5 ability graph, while confidence policy v1 remains separate.

Scheduled OOP dates are activity proxies, accepted only inside the original event window and on/before the snapshot date. Missing, invalid or out-of-window dates use fixed event start dates conservatively. Credible future scheduled matches are withheld rather than refreshed with a proxy. Finish comparisons also use event start dates. Neither score correction timestamps nor an ongoing event's daily-clamped end date refresh confidence. Profile details disclose proxy counts, last direct-match proxy, last eligible evidence, recent 90-day counts, effective volume and confidence as-of date. Competition names, regions and event formats confer no confidence bonus; there is no reliable canonical Cat1-strength field. Play outside recorded eligible system evidence is unknown.

Snapshots share a policy-versioned key and include the daily as-of date. Schedule changes participate in source fingerprinting; publication gates and existing private role/export boundaries remain enforced. Internal confidence records are bounded by the existing 50,000-edge limit; no per-badge history query is introduced. No canonical player/result/ranking state is changed; the derived background snapshot is saved separately.


The v4 ordinal/source-reader changes are retained by the v5 model. Team tie publication/status, draw scoring rules and new team identity/context mappings are hashed exactly; explicit dated previews retain a five-minute cache, while persisted website scores use the background refresh described below. Source processing remains bounded at 1,000 events, 256 fields per event, 256 entrants per ordinal field/team roster, 5,000 players, 5,000 team sources per event and 50,000 topology/played edges or scanned eligible-source records. Any global source overflow withholds the entire estimate. The global individual reader preloads bounded same-event historical membership maps to resolve legacy fields without a per-fixture pair of category queries.


## Main-trial benchmark and supporting evidence (v5)

The reviewed main-trials classifier is event type ID 5 whose type-record name exactly normalizes to `Cavaliers Trials`. Individual event names do not confer benchmark status. Interprovincial trials (including event 217) remain supporting evidence. The latest completed, published main-trial event with eligible played evidence is selected independently per exact cohort. Empty, invalid, unpublished, ongoing and future trials do not replace an earlier eligible benchmark. No absent U9/U10 benchmark is invented.

Canonical main-trial finishing ranks are unavailable in the reviewed historical dataset. Therefore the baseline is explicitly **model-derived from validated trial matches**, never represented as published finishing order. Each event/cohort first receives a per-player incident evidence budget of one: each played edge gets 1 / max(winner degree, loser degree) before its own 180-day decay. Logging more matches in one event alone cannot inflate a perfect repeated-pair result. Actual unique played records and own confidence counts remain intact.

Fit the selected main trial's budgeted played outcomes without age decay. Choose its largest validated connected match group (deterministic lowest-player-ID tie), retain its centered strengths capped at ±1 as targets, and disclose covered players versus all eligible trial players. Disconnected trial groups are not silently assigned equal absolute strength: they remain supporting/local groups until actual evidence links them to the benchmark. The chosen trial component and event/date are retained as provenance.

Each selected player's zero-centered regularizer is replaced by a Gaussian prior at that trial target, with weight 2 × the trial date's 180-day decay. Target values are not themselves age-decayed. The main trial's anchored match edges retain topology/provenance/direct-confidence counts but are omitted from later played likelihood, preventing duplicate use of those outcomes. Supporting match events are budgeted independently; weak ordinal constraints remain weight 0.2. Repeated genuine changes across distinct later events can adjust the baseline; there is no hard point cap. Anchored components are not recentered after fitting. Components without a benchmark retain local centering and an explicit unavailable-reference warning. No event/region-name importance multiplier is introduced.

Profiles and private badge tooltips distinguish direct main-trial baseline, indirectly linked reference and no connected main-trial reference. Confidence policy remains based only on the player's own eligible evidence and receives no freshness/volume bonus from benchmark selection. Version 5 invalidates earlier derived snapshots, including development V4 snapshots. Exact event-type name hashing protects the semantic classifier alongside existing publication/context hashes. These are uncalibrated model assumptions, not official UTR, rank, accuracy probability or selection policy.

### Saved nightly calculation

The private V5 calculation is materialized into the singleton `player_ability_snapshots` record. It stores the calculated cohort graph and compact player badges, confidence, source/policy versions, as-of date, successful build timestamp, source fingerprint, required publication/context manifest and the exact stable weighting rules. These are derived estimates, not canonical player attributes or ranking positions. The formula is not automatically re-tuned or trained overnight.

The scheduler runs `player-ability:refresh --pending` every minute in a separate background process. Committed source mutations, including bulk score corrections/deletions and publication changes, increment a durable generation marker. Multiple changes are combined into one refresh; the formula remains unchanged. Markers run after commit, so scoring transactions hold no shared marker lock and rollbacks discard their callbacks. A five-minute idle fingerprint check recovers external SQL changes or a process crash between commit and marking; exact result values are hashed even when timestamps/counts remain unchanged. Failures back off for five minutes. The midnight `Africa/Johannesburg` refresh remains as recovery and daily evidence ageing, also in the background.

Scheduler overlap prevention and a shared command-level file lock serialize scheduler/manual invocations on the current host. This does not claim coordination across multiple hosts. A complete, converged calculation with unchanged sources replaces the record atomically; failures keep the previous successful record. Only the generation captured at build start is consumed, so later changes remain pending. Continually changing sources can delay a successful replacement; typical minute cadence is not a guaranteed completion time. Older/future/incompatible candidates are rejected. No ordinary profile, table, draw or badge request calculates the graph. An explicit historical as-of preview still performs a separate calculation.

Reads show the saved calculation date and mark old records stale. Captured publication revocation/deletion or source identity/cohort context changes withhold the saved estimates immediately. Newly published sources and fresh results wait for the next background refresh; they do not make a request calculate anything. Super Admin sees last-updated, pending and failure status. Open pages check the private revision every minute and refresh HTML/SVG badges when it changes; hidden tabs pause those checks. Status and badges share the same request snapshot revision to prevent stale badges being cached as a newer snapshot. Publication/context checks are bounded and scoped to calculated-source events and participant identities. Missing schema, missing snapshots or policy mismatch show Pending. Estimates remain available only to Super Admin; shareable exports continue to omit them.

Operational commands: `php artisan player-ability:refresh --check` reads readiness only, including same-day pending/failure state; `--dry-run` calculates and validates without writing the saved snapshot; an unqualified invocation replaces it. Saved scores require `database/migrations/2026_10_07_000001_create_player_ability_snapshots_table.php`; background tracking also requires the exact `database/migrations/2026_10_09_000001_create_player_ability_refresh_state.php`. Both paths are allowlisted in `deploy.config`. The minute command fails safely if its state migration is absent; score entry continues. The Laravel scheduler must run on the application host and be able to launch background PHP commands. Local development does not authorize production migration, scheduler activation or deployment. No live scheduler/cron activation has been performed.

### Structural confidence display and retrospective validation

Confidence labels also account for comparison uncertainty. High requires an internal index of at least 70, at least five own played matches, a direct main-trial baseline and a component with neither inferred links nor narrow bridges. Indirect/unavailable trial references, inferred/bridge links or incomplete structural metadata cap the visible label at Medium; no own played evidence remains Low. Low remains Low. Existing saved snapshots are normalized using their stored full cohort/component data when read; the ability/index formula, saved policy hash and model version are unchanged. Labels describe recorded evidence strength/freshness, not calibrated accuracy, and tooltips/profile details explain structural cautions.

`php scripts/validate-player-ability.php --event=ID` is a CLI-only, aggregate read-only validation tool. It bootstraps Laravel directly, avoiding Artisan lifecycle audit writes, and uses a read-only database transaction with rollback. It never refreshes saved snapshots or writes caches. It holds out one completed, currently published event in full: training includes only events with valid original end dates strictly before the holdout starts. Entire held-out/overlapping/unfinished events, including finishing-order constraints, are excluded. Current publication and identity records are used, so this is retrospective validation, not a reconstruction of what was historically available; conservative date proxies remain a limitation.

The JSON report contains counts only: training-event and per-cohort player/missing-endpoint diagnostics, eligible versus compatible rated coverage, higher-rated win rate excluding separately reported tied-rating pairs, Brier score, log loss, and conservative pair-confidence groups. Probabilities are sigmoid differences of raw fitted strengths, not the displayed 0–100 scores, and remain uncalibrated. Different cohorts/components and missing/withheld pre-event ratings are excluded explicitly. Direct selected-trial reference predictions are reported where both participants have the same benchmark, alongside current predictions on exactly those pairs; their restricted coverage is distinct from full-model coverage. No names, player-level predictions or private snapshot payloads are emitted. Source changes or processing/fit failures withhold the report. No ability weights are tuned from these measurements.

## Score margin (v7)

The validation command also accepts `--events=ID,ID` for up to ten event IDs, returning separate holdout reports without pooling accuracy across events. Duplicate IDs are evaluated once; choose either `--event` or `--events`. Every report includes a 50/50 chance reference on exactly the evaluated pairs, source-specific yielded/duplicate/eligible/evaluated counts, and exclusion reasons. Raw event fixture candidate counts include unpublished/unplayed/doubles records; canonical readers may prefilter these without yielding a rejection reason. Candidate counts therefore describe scope, not eligible singles coverage. `no_evidence` means no eligible holdout singles; `insufficient_coverage` means none have compatible pre-event ratings; `partial_coverage` means only some eligible singles were evaluated; `evaluated` means all eligible singles were evaluated. None of these statuses establishes calibrated predictive accuracy or a sufficient sample size.

Validated played singles use winner target 0.75 + 0.25 x max(0, average signed set margin). Each set margin is (winner-side score minus loser-side score) / total score. A 6-0, 6-0 win targets 1; 7-6, 7-6 targets about 0.769. The loser receives the complementary target. Winning fewer total games never reverses the declared match winner: the floor remains 0.75. Targets describe a conservative heuristic, not calibrated probabilities.

Each set contributes equally after normalization: a deciding match tiebreak contributes a point share without its points being added to games. Known short/full/pro formats work through their canonical format definitions. Custom formats and unknown legacy/team sets with scores of 10 or more use the conservative outcome-only target 0.75 because their units cannot be verified. Ordinary legacy/team game sets below 10 use the normalized margin. Eligibility, publication, decay, event budgets, topology and confidence counts are unchanged. Main-trial anchors include the targets during baseline fitting; their later topology-only edges remain excluded to prevent double counting. No historical scores are rewritten.

Model version 7 and margin policy version 2 invalidate earlier derived snapshots. Ordinary requests show Pending until the authorized background calculation rebuilds compatible estimates. Local implementation does not rebuild production snapshots.

### Read-only experimental comparisons

Add `--compare` to either validation command to refit only the pre-event training universe with half and double the current main-trial anchor weight. Reports compare current and alternative loss on the identical compatible pairs, separately per cohort. Negative Brier/log-loss differences favor an alternative on that selected sample; no automatic promotion or snapshot write occurs. Confidence single-decay removes only the additional latest-match multiplier: predictions stay identical and only confidence stratification changes. These policies do not change normal ratings or labels.

Experimental conditional information is the diagonal of the regularized fit Hessian with all opponent and field-peer strengths held fixed. The pair strength standard-error approximation sums conditional variances, omitting covariance, source dependence and trial-baseline estimation uncertainty. It is an uncalibrated sensitivity diagnostic, not a joint posterior interval, confidence percentage, or accuracy claim. Nonconverged fits are withheld. `small_sample` flags fewer than 30 evaluated or 20 unequal-rating pairs; passing those thresholds still permits descriptive reporting only. Choose representative completed published events across ages, gender cohorts, event formats and time periods, with up to ten separate holdouts per command; do not select only events that favor a policy.
