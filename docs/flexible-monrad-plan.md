# Flexible Monrad implementation plan

## Agreed workflow

Create a separate Flexible Monrad format. Start with an empty bracket and an eligible-player list. Drag a player into an available starting slot, or select a slot and click a player. Support entry in different rounds, moving, swapping, removal, explicit byes, undo, draft saving and preview before publication.

Initial competition rule: full placement by the round in which a player leaves the main draw. Direct quarterfinal entrants are guaranteed a top-eight finish. Display this rule prominently. Winner and loser paths are generated automatically; arbitrary manual rewiring is outside this release.

## Implementation sequence

1. Add a versioned draft record and register the format without assuming a numeric format ID.
2. Compile the starting slots into an explicit acyclic match graph. A source is a player, match winner, match loser, or bye; unresolved draft slots are never byes. Generate exact placement paths for uneven fields.
3. Persist generated matches in the existing fixtures table. Keep the source graph separate from resolved participants. Serialize mutations using a draw lock and revision checks. Prevent legacy generation/scoring from processing this format through incompatible rules.
4. Build the clickable/draggable editor with search, undo, conflict messages and branch-aware placement. Provide a non-persistent 22-player demo.
5. Implement publication, scoring, guarded result correction, public display and browser printing. Freeze assignments once generated; corrections with scored descendants require an explicit reset showing affected matches.
6. Verify compiler properties and HTTP authorization, isolation, stale revisions, generation idempotency, byes, winner/loser progression, corrections and publication. Check routes, Blade compilation, PHP syntax, JavaScript syntax and browser behavior.

## Acceptance example

Sixteen players start in the round of 32, four in the round of 16, and two in the quarterfinals: 22 unique starting assignments, six round-of-16 matches, four quarterfinals, and exact final positions 1–22. Direct placement must never silently delete an occupied earlier branch. Desktop drag/drop and mobile click-to-place must offer the same placement actions.

## Release

Run only the required Flexible Monrad migration and `2026_09_02_170000_add_gap_minutes_to_order_of_plays_table.php`. The gap migration has been applied locally; existing bookings default to zero gap because historical gaps were not stored. No production deployment is included.

## Implemented and verified

- Local demo: `/flexible-monrad/demo`. The 22-player example uses dummy names and does not create event records. Demo scoring stays in the browser; optional draft saving uses this device's local storage.
- Actual draw: open Manage Draw → Open Monrad editor. Assign eligible, active category registrations; save; generate; review; publish. Use Edit starting positions to reopen an unpublished, unscored and unscheduled draw.
- Supported starting layouts: 4, 8, 16, 32 and 64 slots. Unused paths must be explicitly marked as byes. Full classification supports uneven player counts.
- Winner-changing corrections identify scored descendants and require an explicit reset. The audit retains the reset results and original participants.
- Withdrawals preserve completed matches and player identities. Apply withdrawals (or save another result) to reconcile unplayed fixtures: an active opponent advances by walkover, a fully empty branch closes, and an unresolved opponent remains pending. No set scores are fabricated. Closed-match schedules and withdrawn draw memberships are removed; category/financial withdrawal state remains owned by the existing entry lifecycle.
- Withdrawn players are labelled and excluded from final positions. The original placement bands remain intact, so some positions can be unassigned after withdrawal. Once reconciled, a withdrawn entrant cannot silently re-enter the generated graph through a category-status change. Result correction still requires explicit reset of any played descendants.
- Public views project withdrawal effects without writing records. The editor offers Apply withdrawals while fixture/schedule reconciliation is pending. Historical names are loaded independently from the eligible-player picker.
- Legacy individual scoring endpoints are rejected before any result writes. Existing venue add/remove/sync controls retain their normal event authorization and lock/publication rules.
- Name-only updates work through the existing draw settings routes. The Monrad settings form submits only the name; mixed payloads that attempt structural changes remain blocked, as do edits by other event administrators or edits to locked/published draws.
- Entry eligibility excludes all withdrawal/refund sub-states, cancelled entries, soft-deleted memberships and any recorded withdrawal timestamp. Reconciliation compares automatic-outcome maps independently of JSON key order, so unchanged outcomes do not increase revisions or create audit entries.
- Progression follows source dependencies recursively rather than relying on JSON key order, which MySQL does not preserve.
- Monrad auto-scheduling follows both winner and loser dependencies across all placement sections, waits for feeder matches to finish and allocates free courts. It preserves played matches, omits automatic walkovers/closed branches, records match duration and clears closed-match schedule flags. Scheduling is serialized with draw mutations and repeat plans are idempotent.
- Manual time changes check qualifying and dependent match times as well as existing court/player conflicts. Use the individual auto-scheduler for Monrad; legacy round-only/trials bulk scheduling cannot safely identify its separate placement rounds and is guarded.
- Reset now delegates directly to the transactional Monrad planner: invalid input or a published draw leaves the timetable intact, and successful resets preserve played-match times. Auto-scheduling skips existing bookings from other draws on the same venue/court, including future bookings that overlap a proposed match. Monrad auto/manual writes lock shared venue records; manual writes also update the draw revision. Removing an unplayed feeder's time is rejected until scheduled descendants on both winner and loser paths have been removed.
- Individual scheduling now shares `ScheduleAvailability` across Monrad and the legacy whole-draw, round and single-fixture paths. Court reservations work in either scheduling order; participant reservations follow player membership across registrations and venues. Unresolved Monrad fixtures reserve their possible entrants for other draws until results identify them. Within a Monrad draw, winner/loser dependencies determine availability so disjoint placement matches can still run in parallel. The individual schedulers serialize changes within an event and lock shared venues; auto-scheduled legacy fixtures now retain duration and scheduled flags.
- Legacy bracket scheduling also follows winner and loser fixture links, including placement branches with different round numbers. Finals wait for delayed feeders; manual moves/removals cannot break those dependencies. The trials route now uses this same transactional scheduler and shared availability, retaining bracket/round filters, first-round byes and inter-match gaps. Filtered updates require unscheduled qualifying matches to be included, and cannot overrun dependent matches outside the selection. Invalid/circular dependencies roll back all writes. Schedule reset no longer clears before planning for either draw type. The test-only schema includes the existing application `fixtures.bracket_id` column; no production migration is required for these fixes.
- Monrad scores now require completed standard tennis sets (6–0 through 6–4, 7–5 or 7–6) and the configured `num_sets` match length (best of 1, 3 or 5; defaults to 1 when unset). Extra sets after the match is won and incomplete matches are rejected. The demo uses one set and the same completion rules. Short sets, pro sets, match tiebreaks and retirement scores need explicit future format settings; they are not inferred from arbitrary numbers.
- Follow-up scheduling fixes: a first-round empty participant slot is inferred as a bye only when no winner or loser qualifier feeds the match. Each booking now stores its turnaround gap separately from match duration. Filtered trials reruns, manual dependency checks and shared court/player availability preserve that gap. Manual edits retain the booking's saved gap; new Monrad auto-schedules use zero gap. These fixes require the gap migration listed above.
- Manual saves from the individual and trials screens preserve stored match duration when the request omits it or sends null. The scheduler resolves the duration while holding the draw/fixture locks; explicit duration changes still undergo validation and conflict checks. New bookings without a duration use 75 minutes.
- Shared availability also reserves possible participants in scheduled legacy matches with unresolved winner/loser qualifiers, including chains of qualifying matches and registrations belonging to the same player. Recorded winners narrow each path to its actual winner or loser, and fully resolved matches use their assigned participants. These reservations prevent Monrad auto-scheduling and manual edits from overlapping a pending legacy final at another venue. These follow-up changes require no additional migration.
- Legacy scheduling now derives possible participants for the match being scheduled as well, so protection works in both directions. Whole-draw, trials, filtered trials, round-only and manual changes respect existing Monrad reservations. Within the same draw, dependency checks and resolved participants allow disjoint winner/loser placement matches to run on separate courts at the same time.
- Booking ownership is read through the linked fixture. Historical trials rows with a null booking `draw_id`, including partially updated schedules, remain visible to participant checks without a database backfill or additional migration.
